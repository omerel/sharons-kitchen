# שימוש בדמו כבסיס לפיתוח ב-Claude

הקבצים `index.html`, `styles.css`, `app.js` הם **אבטיפוס חזיתי מדומה** שנועד לאישור חוויית שימוש. הקובץ `Sharon_Kitchen_Interactive_Demo.html` הוא אותה מערכת במבנה HTML יחיד.

## מה לשמר
- העיצוב בעברית RTL והתאמה לנייד.
- תצוגת לקוח: בית, תפריט, מודאל פרטי מנה, סל, Checkout, הוראות תשלום, מעקב הזמנה ובקשת שינוי/ביטול.
- תצוגת מנהל: דשבורד, מחזורים, קטלוג, הזמנות, תשלומים, בקשות שינוי, דוחות, הגדרות והרשאות.
- הפעלה והסתרה של אפשרות משלוח דרך מתג גלובלי (איסוף עצמי ברירת מחדל), מחיר משלוח קבוע וחלונות אספקה נפרדים.
- מכסות משקל כוללות לכל מנה במחזור, ומגבלות מספר הזמנות לכל חלון.
- 24 שעות לתשלום — **אין ביטול אוטומטי**. מנהל יכול לבטל ידנית.
- יומן תנועות תשלום/החזר ידניות וחישוב יתרה לאחר שינוי.
- דוח הכנה מסונן לפי כלל ההזמנות/שולמו בלבד ודוח אריזה מרוכז/דף לכל הזמנה; Excel והדפסה.

## מה לא להעתיק כפתרון ייצור
- `localStorage` אינו מסד נתונים ואינו מאובטח למידע אישי.
- מעבר ל"תצוגת מנהל" אינו אימות/הרשאה.
- "כניסה עם Google" מדומה; בייצור נדרש OAuth.
- אין API או תשלומים/העברות אמיתיים.
- בדיקות מכסה בצד לקוח אינן אטומיות; בייצור נדרשת טרנזקציה במסד.
- הודעות אימייל ו-WhatsApp אינן נשלחות; WhatsApp אוטומטי נמצא רק בגרסה 1.1.
- נתוני התפריט, התמונות, פרטי העסק, הכתובות והמחירים הם דוגמאות.

## הנחיה מומלצת ל-Claude

> קרא תחילה את מסמכי האפיון המלאים בחבילת המפרט של המטבח של שרון, ולאחר מכן את קובצי הדמו. שחזר את העיצוב והאינטראקציות ב-Next.js + TypeScript ו-Supabase/PostgreSQL, אך החלף את כל פעולות `localStorage` וגישות הניהול ב-API מאובטח, RLS, טרנזקציות הזמנה אטומיות ואימות Google אמיתי. פתח כל רכיב בשלבים ותכנן בדיקות End-to-End. אל תוסיף ל-MVP דירוגים, מועדפים, היסטוריית הזמנות חוזרות או WhatsApp אוטומטי ללא אישור.
